# Qline v1.10.0

**GitHub for code: the AI can read your repositories and CI, and propose code changes and pull requests you approve.**

- **Read code.** Browse repositories where the Qline GitHub App is installed, open folders and files (big and binary files are skipped, secret-looking values hidden), search code, and follow branches and commits.
- **Pull requests and CI.** See a PR's files, reviews and checks, the Actions runs for a branch, each job's steps and the end of a failed log.
- **Changes you approve.** Ask the AI to fix something: it creates a working branch, commits the changed files and opens a pull request (draft if unsure). Each step waits in **Approvals** with a coloured diff. It can also edit a PR's text and leave a comment or "request changes" review.
- **Hard limits.** Qline never commits to the default or a protected branch, never merges, force-pushes or deletes branches, never edits GitHub Actions workflows and never reads secrets. It never approves a pull request. If the branch moved after you saw the diff, the change is refused instead of overwriting.
- **Always asks.** GitHub changes now always need approval, even on full autopilot (this includes opening issues and commenting, which full autopilot used to do alone).
- **New screen.** **Integrations → GitHub → Code, pull requests and CI** shows what the app may do, which GitHub permission turns on anything missing, and any risky permission the app has but Qline never uses.

**GitHub App setup:** add Contents (read and write), Pull requests (read and write), Actions (read), Checks (read) and Commit statuses (read), then accept the new permissions on each installation. See [docs/24](../24-GITHUB_INTEGRATION.md).

**Server:** production runs API 1.10.0 (Neon function deployment #16) with migration 0025, applied 2026-11-20.

Not in this release: merging, re-running workflows, editing workflows, GitHub webhooks.
